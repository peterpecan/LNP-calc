# LNP calculator

A browser-based lipid formulation calculator based on `240925 LNP.xlsx`. Runtime assets are bundled locally; no backend or account is required. Recipe data stays in browser storage, and JSON backups move saved recipes between devices.

Open `../LNP-calculator.html` (generated by `npm run build`, or downloaded from the Pages workflow run) directly in a browser for the self-contained app. All code and styles are embedded, and no internet connection or server is required. Keep a JSON backup of saved recipes, especially when moving or renaming this file, because browser storage behavior for local files varies.

For development, run `npm start` from this directory and open `http://127.0.0.1:4173`. Run calculation checks with `npm test` (Node.js 18+). Edit files in `src/`; the preview serves them live. Run `npm run build` to regenerate `dist/`, the single-file app and the Pages output.

The default recipe preserves the worksheet's five stock concentrations in mM and reproduces all aliquots. DSPC's molecular weight is corrected to 790.145 g/mol for mass calculations, with a visible stock discrepancy note. DSPE-PEG-MAL molecular weight is deliberately blank pending the exact product specification; select DSPE-PEG(2000) maleimide from the lipid library if that is your product. See Worksheet review in the app for the source audit.

Ratios are normalized, stock volumes calculated without intermediate rounding, and ethanol fills the remaining phase volume. A negative solvent balance blocks export. Mass concentration inputs require a positive molecular weight. Every output scales with batch count and preparation overage.

## Lipid library and mass-based stocks

Type in a lipid name field to pick a library match, which replaces that row while retaining its molar parts; **Browse lipid library** opens the full library and adds a row. The library includes 16 supplier-referenced ionizable, helper, PEG, sterol, and cationic lipids, including MC-3, SM-102, ALC-0315, DSPC, DOPC, DOPE, cholesterol, and several PEG lipids. Selecting a material fills its molecular weight and clears the previous material's stock concentration. Enter the stock for the material actually on your bench.

Choose **mass ÷ volume…** in a stock unit menu to enter lipid mass in mg and final stock solution volume in mL. For example, 100 mg in a final volume of 4 mL gives 25 mg/mL. The app calculates the equivalent mM using the selected molecular weight and uses the mass concentration to determine aliquots. You can also enter mg/mL or mM directly; switching units preserves the physical concentration when a molecular weight is available. Direct concentration edits clear the previous preparation details.

Molecular weights remain editable for the exact product or lot. Each built-in entry links to its supplier reference and identifies the chemical form or salt. PEG molecular weights are averages. A different counterion, PEG distribution, or product specification may require an override; overrides are labeled. Library values are copied into each recipe, so later library changes cannot silently alter saved recipes.

**Add a lipid to your library** saves custom entries in this browser. Recipe JSON, QR transfers, Excel, and CSV retain the selected reference and any recorded mass/volume inputs. Unused custom library entries are browser-local. Excel exports include editable preparation inputs linked by formulas to the calculated stock concentration. In a lab session, mass/volume changes preserve the original plan and clear pipetting checks.

## Office to lab workflow

1. Plan a recipe in Calculator. **Start lab session** freezes the original plan and opens Lab session.
2. **Share / export → Send to phone (QR)** generates a QR and recipe link in the browser. **Send…** passes the link to the device's share menu where supported; use it to send a prepared session back from the phone too. Built-in library lipids travel as a short ID checked against the receiving app's library, so both devices need the same app version. Scanning opens a preview; accept it to open the recipe in Lab session. Any unsaved draft or lab session on the receiving device is first kept in Saved recipes (a parked session shows **Resume session**). Opening a saved record or the starter recipe works the same way.
3. Lab session shows large stock concentration controls, units, optional MW fields, live aliquots, ethanol top-up, and pipetting checkboxes. Targets and original stock values remain available for comparison. Any stock change clears pipetting checks and marks a previously prepared session as edited.
4. **Save prepared record** adds a new independent record containing both the original plan and actual values. Later edits do not modify saved records.
5. Export Excel, CSV, or JSON. Excel includes numeric inputs, cached full-precision results, formulas for recalculation in Excel, an original-plan tab, and a QR transfer sheet when a website address is set and the recipe fits a QR. CSV also includes the original plan for active sessions. JSON exports preserve prepared sessions and can be imported on another device.

Transfers are snapshots and do not synchronize devices. A browser-local working session resumes after reload. Existing v1 recipe backups remain supported. Importing a prepared record retains both versions.

## Offline and hosting

The single-file HTML works offline without installation. The hosted multi-file app caches its assets after its first successful online visit and displays **Available offline**. A phone can use Add to Home Screen / Install where supported. Browser storage and offline caches can be cleared by the browser; keep backups. HTTPS is needed for caching on phones, except for desktop localhost development.

`npm run build` copies `src/` to `dist/`, bundles vendor dependencies, generates icons and the service worker, and creates the portable and public outputs. `npm start` serves the local app at `/` and the generic GitHub Pages build at `/pages/`. See [HOSTING.md](HOSTING.md) for deployment instructions, phone testing, QR privacy, and transfer limits. Only the generated `github-pages` folder is deployed; local source contains the original worksheet default.

The workbook is not included in the build.

## Visual design

Styles use the tokens in `src/workspace.css`; `npm test` checks palette contrast. Rebuild with `npm run build` after changing assets, then check desktop, wide-screen, and phone layouts.
